# MyBlog Tone — 사용자 블로그 톤 가이드

이 사용자의 블로그 톤은 **두 결의 결합**이다:
1. *진중함 + 셀프디스 + 깐족이 한 글에 섞이는* 후루꾸식 결
2. *강도 있는 감탄 + 추천/비추천 명확*한 사용자 본인의 결

이 두 결을 합치되, **다른 블로거의 시그니처는 차용하지 않는다.**

---

## ★ 근본 기준 — 단 하나

> **내가 쓰고 내가 읽었을 때 재밌는가.**

이게 이 사용자 블로그 톤의 *유일한 평가축*. 독자 재미를 따로 계산하지 않는다.
*내가 쓰면서 재밌는 글*이 결과적으로 독자에게도 재밌다는 후루꾸식 철학.

아래 모든 가이드(살릴 것·뺄 것·체크리스트)는 이 단일 기준의 *검증 도구*일 뿐.

### 판단 방법

다 쓰고 처음부터 읽어보기. 세 가지 체크:

1. **멈추지 않고 끝까지 읽히는가** — 중간에 졸린 단락 있으면 그 자리가 *분석체*. 잘라내거나 *반응체*로 교체.
2. **한 번 더 읽고 싶은 구간이 1~2개 있는가** — 결정타·작은 일화·옆길 중 하나.
3. **추신까지 다 읽고 조금 더 쓰고 싶은 자리가 남아있는가** — 글이 *닫혔는지 열렸는지*의 시그널.

### 옵시디언 분석체 vs 블로그 반응체

블로그는 *반응 공유 + 공감 끌어오기*의 자리. 옵시디언에서 *분석* 끝낸 것 위에서 쓰는 글.

근데 **분석 자체가 나쁜 게 아니다.** *"왜 재밌는가" "왜 박혔는가"*를 짚는 분석은 반응체의 *척추*다. 이게 빠지면 글이 평면화됨 (감탄만 남고 근거 없음).

문제는 *거리감 있는 학술체 톤*. 그게 분석체.

- ❌ 분석체 (거리감 있는 학술체): "이 게임이 좋은 이유는 도덕·부자성장·운명론 4축이 동시에 풀리기 때문이다."
- ✅ 반응체 (내 반응 + 왜 재밌는지 분석): "이게 제일 큽니다. 단순 권선징악 같은 일차원이 아닙니다. 도덕·부자성장·운명론 4축이 동시에 풀려요."

→ *같은 분석*을 *내 반응의 근거*로 풀면 반응체. 거리 두고 *제3자가 평가하듯* 풀면 분석체.

분석은 *필요할 때 필요하다*. 다만 *내 반응*과 묶여있어야 함.

## ✅ 살릴 것

### 글의 근본 구조 3가지

블로그 글이 *살아남기 위한* 세 자리. 하나도 없으면 글이 죽는다. 변환 시 *이 셋 중 약한 자리*가 있으면 보강 1순위.

1. **결정타 한 문장** — 작품의 *한 결*이 한 문장으로 박힘
	- 예: "인생 게임을 위에서 갈아치우는 작품 6년에 한 번 올까말까"
	- 예: "다 깨고도 투기장 갔다"

2. **시작점** — *왜 이 글을 쓰는지* 도입 1단락에 신호
	- 예: "제 인생 게임은 여러 개 있습니다... 근데 라그나로크가 그 자리를 *위에서* 갈아치웠습니다"

3. **작은 일화** — 본문 중 *그때의 내 반응* 한 컷
	- 예: "도끼로 캐치볼 ㅋㅋ 개꿀잼"
	- 분석 100문장보다 *반응 1컷*이 글을 살림

### 호흡

- 한 단락 1~2문장으로 압축
- 빈 줄 자주 넣어서 시각적 호흡 짧게
- 한 호흡으로 길게 쓴 분석체 ❌ → 짧게 끊어서 ✅
- **짧은 정보·캡션 라인 별도 배치**: "PS5 스탠다드", "낭만 가득", "도끼랑 갑옷 디테일 봐라. 미쳤다." 같은 한 줄짜리 정보·감상은 본문에 녹이지 말고 *별도 라인*으로 띄우기. 이미지 캡션이나 짧은 메모도 마찬가지.

### 작품 나열은 여러 개로

사용자는 인생 게임/책 후보가 *여러 개*다 (젤다·바이오쇼크·어크 오디세이·킹덤컴 등).
한 개로 단정하면 톤이 어색해짐.

- ❌ "제 인생 게임은 두 개였습니다. 바이오쇼크랑 갓오브워4."
- ✅ "제 인생 게임은 여러 개 있습니다. 젤다의 전설이랑 바이오쇼크, 어크 오디세이, 킹덤컴 등등"

→ 후보 *여러 개* 나열하고 "근데 이번 작품이 그걸 *위에서* 갈아치웠다" 식의 흐름이 자연스러움.

### 정확한 명칭 보강

AI가 두루뭉술하게 쓴 표현을 사용자는 *정확한 부가 정보*로 보강하는 습관이 있음.

예시:
- "PS5 독점" → "PS5 독점입니다.(지금은 풀림)"
- "투기장" → "DLC인 발할라의 투기장"
- 캐릭터 풀네임, DLC 정식 명칭, 아티스트 정식 표기 등

→ 변환 단계에서 *가능하면 정확한 명칭*으로 쓰기. AI가 단순화한 자리는 사용자가 보강 1순위 자리임을 인지.

### 정중체 + 반말 자유로운 섞기

- "~합니다", "~이에요", "~인데요"
- "~거든요", "~더라고요"
- "이게 뭐냐면", "근데 진짜", "이게 맞나?"
- "암튼", "별 건 없는데 굳이 꼽자면"
- "~인 듯", "~같음"

### 강도 있는 감탄 (사용자 시그니처)

- "미쳤다", "지렸다", "독보적임"
- "강추"
- "이만큼 ~한 게임/책/영화가 있을까"

**중요 규칙**: 감탄 직후 *왜* 그런지 1단락 따라옴.
감탄만 던지고 끝내면 AI식. 감탄 + 근거 = 사용자 톤.

### 약한 욕설 (강조할 때만)

- "개", "ㅈㄴ" — OK, 한 글에 1~2번
- ❌ 절대 금지: "시발", "씨발", "병신", 그 외 강한 욕

### 옆길 빠지기

- 한 글에 0~1번. 너무 엇나가지 않게.
- 짧게, 본론으로 빠르게 복귀.

### 추신 형식

- `+`, `++`, `+++`, `++++` 사용
- **4개+까지 자유롭게**. 추신이 길어져도 OK.
- 본문에 안 들어간 짧은 코멘트
- *플레이 영상 캡션*, 별첨 디테일도 추신 자리에 OK
- 마지막 추신엔 *가벼운 디테일* (예: "도끼로 캐치볼 하기 ㅋㅋ 개꿀잼")로 페이드 아웃
- 자조 유머 OK

### 사용자 시그니처 어휘 (보존만, AI 새로 만들지 X)

다음 어휘는 사용자의 *자생적 표현*. 본문 변환 시 사용자가 직접 넣은 부분이면 *보존*하되, AI가 *새로 만들어 끼워넣지는 않는다*.

- **"하이"**: 머리에서 *깨달음/사유가 떠오르는* 느낌. 영어 "come up with"의 한국어 시그니처.
	- 예: "메인급 사유를 하게끔 *하이*가 옵니다"
- **"츄라이 츄라이"**: 강추할 때 사용자 시그니처 마무리.

이외에도 사용자 글에서 *처음 보는* 표현이 등장하면 *임의로 따라 쓰지 말고* 사용자가 직접 넣은 부분에서만 보존.

### 이미지

- 메인 비주얼 맨 위
- 큰 섹션마다 1개 정도
- `[Image: 어떤 사진]` 자리 표시 + *캡션 한 줄*

## ❌ 뺄 것

### em dash (`—`)

**한국 글에선 거의 안 씀. AI 티 가장 강함.**

대체:
- 마침표로 끊기
- 괄호 ( )
- 쉼표

### 평면적 형용사 (알맹이 없음)

- "진짜 좋은 게임이었습니다"
- "정말 재밌었어요"
- "100시간 박았는데 아깝지 않음"
- "추천드립니다"

→ 어떤 작품에든 갖다 붙일 수 있는 클리셰. *근거 없는 감탄*은 AI식.

### 이모지·과한 이모티콘

- ❌ 진짜 이모지 (🎮 🔥 ✨ 등)
- ❌ `^^`, `;;`, `ㅠ`, `ㅎ` 자주
- ✅ `^^` 1번까지 (예: "용서했다 ^^" 같은 자조 자리)
- ✅ `ㅋㅋ` 1~2번까지

### 다른 블로거 시그니처 따라하기

- ❌ "레지고" — 후루꾸 시그니처
- ❌ "끝." 단정 마무리 — 후루꾸 시그니처
- ❌ "이 문과색히야!!!" 같은 가상 캐릭터 대화 — 후루꾸 스타일

→ *영감*은 OK, 그대로 가져오는 건 X. 사용자의 자연스러운 도입과 마무리를 만들 것.

### 단정적 마무리 X

- ❌ "끝."
- ❌ "이상입니다"
- ✅ 추신으로 자연스럽게 페이드 아웃

## 변환 예시

### 노트 원본 → 블로그 변환

**원본 (옵시디언)**

> 복수라는 감정이 결국 파멸과 공허로 남긴 하지만, 그로 인한 헨리의 과정을 세세히 만들어 갔던 거 같다. 지금 생각해보니.

**블로그 변환**

> 게임이 보여주는 핵심 메시지는, **복수가 결국 파멸과 공허로 남긴다**는 거예요.
>
> 근데 이게 그냥 "복수는 나쁩니다" 같은 일차원 메시지가 아니라, 헨리가 *그 과정을 직접 겪게* 만들면서 보여주는 식입니다.

→ "지금 생각해보니" 같은 자기 검토 표현 빼고, 정중체로 풀어서 *독자에게 보여주는* 톤.

### 4차원 평점 → 추천/비추천

**원본 (옵시디언)**

```
craft: 8/10 — 검술 카운터 시스템과 승마...
narrative: 9.5/10 — 이만큼 중세를 녹여낸...
impact: 10/10 — 길 가다가 인카운터...
rewatch: 7/10 — 큰 스토리는 다 알아서...
```

**블로그 변환**

```
**무조건 추천**: 시대물 좋아하는 사람, 진중한 RPG 좋아하는 사람, 1편 한 사람.

**비추천**: 화려한 액션 원하는 사람, 빠른 진행 좋아하는 사람,
시대 배경 자체에 관심 없는 사람.
```

→ 평점 근거를 본문 좋았던 점/아쉬운 점에 *녹이고*, 마지막에 명확한 추천 결론.

### "함께 읽기/플레이" → 추신

**원본 (옵시디언)**

```
## 함께 플레이하기
- 디트로이트 비컴 휴먼 (선택의 분기 비교)
- 1편 [[킹덤 컴 딜리버런스]]
```

**블로그 변환**

```
\+ 1편 했으면 *반드시* 해라. 헨리 알고 보면 감동 1.5배.

\++ 빌드 다양성은 좀 부족함. 다른 빌드로 다시 깰 매력은 적다는 게 단점이라면 단점.
```

## 플랫폼별 미세 조정

### 네이버 블로그

- 줄바꿈이 *시각적으로* 매우 중요. 빈 줄 더 자주.
- 이미지 자리 명확히. 사진 캡션 한 줄.
- `**굵게**`는 잘 작동, 코드 블록은 안 어울림.

### 티스토리

- 마크다운 그대로 작동. 코드 블록 OK.
- 줄바꿈은 네이버보다 덜 빠듯해도 됨.

### 벨로그·미디엄·범용 마크다운

- 그대로.
- 단, 벨로그는 개발 블로그 톤이 강하니 코드/기술 안 들어가는 리뷰는 결이 살짝 안 맞을 수 있음.

## 자가 점검 체크리스트

변환 끝나고 발행 전에 한 번 더 확인:

**★ 루트 체크 (이게 진짜 평가, 나머지는 보조 도구)**

- [ ] 다 쓰고 처음부터 읽어봤을 때 *멈추지 않고* 끝까지 읽힘
- [ ] 중간에 *졸린 단락* 없음 (있으면 분석체 → 반응체로 교체)
- [ ] *한 번 더 읽고 싶은 구간* 1~2개 있음

**근본 구조 (글의 척추)**

- [ ] 결정타 한 문장 박힘
- [ ] 시작점 (왜 이 글을 쓰는지) 도입에 있음
- [ ] 작은 일화 본문에 1~2컷

**표현 차원 (말투 디테일)**

- [ ] em dash (`—`) 사용 0개
- [ ] 단락당 1~2문장 호흡
- [ ] 강도 있는 감탄 직후 근거 한 단락 따라옴
- [ ] 평면 형용사 ("진짜 좋다", "정말 재밌다") 없음
- [ ] 다른 블로거 시그니처 ("레지고", "끝.") 없음
- [ ] 강한 욕설 ("시발", "씨발") 없음
- [ ] 메인 비주얼 자리 표시 + 캡션
- [ ] 추천/비추천 명확
- [ ] 추신 형식 (`+`, `++`, ...) 자연스러운 마무리
